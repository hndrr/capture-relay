# Capture Relay

Chrome Manifest V3 の **キャプチャ × DOMトリガー** の実験用拡張。TypeScript / Chrome Side Panel。ローカルで処理し、取得したメディアは指定フォルダ（Chrome ダウンロード配下、またはダイアログ選択）に保存します。外部サーバーへの送信はありません。

> **Status:** v0.1 prototype。型チェック、矩形クロップ・保存先パス生成の単体テスト実施済み。Chrome 上での実際の権限ダイアログ・録画・イベント取得を含む自動 E2E テストは未実施です。

## 対応機能

| 対象 | できること |
| --- | --- |
| 静止画（タブ全体・範囲・DOM要素） | PNG 撮影。矩形ドラッグや要素クリックで切り抜き、CSS セレクタを自動入力 |
| 録画（現在のタブ） | `chrome.tabCapture.getMediaStreamId()` によるダイアログなしのタブ録画（映像＋音声 / WebM） |
| 録画（タブ選択／画面・ウィンドウ） | `chrome.desktopCapture.chooseDesktopMedia()` でタブのみ／画面・ウィンドウを出し分けて選択（WebM） |
| 録画の範囲指定・DOM要素切り抜き | 選択した範囲や DOM 要素だけを `<canvas>` 経由で 30fps クロップ録画。ガイド枠の移動・リサイズ・要素追従に対応 |
| マイク録音 | `getUserMedia({audio:true})` による **WAV (16-bit PCM)** 録音 |
| 保存先設定 | ダウンロードフォルダ内のサブフォルダ指定、または保存時のダイアログ選択 (`Save As`) |
| DOM監視・トリガー | CSS セレクタの出現・消失・クリックを検知し、PNG 保存／録画開始・停止／時刻記録を実行 |
| ログ | ローカルストレージへ直近 250 件保存。JSON でエクスポート可能 |

## セットアップ

Chrome 116 以降が必要です。

### リリース ZIP から導入する場合（ビルド不要）

1. [Releases](https://github.com/hndrr/capture-relay/releases) から最新の `capture-relay-v*.zip` をダウンロードし、任意のフォルダに展開します。
2. Chrome で `chrome://extensions` を開き、右上の「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」から、**展開したフォルダ**（`manifest.json` が入っているフォルダ）を選択します。
4. ツールバーの拡張機能メニュー（🧩）から **Capture Relay** をクリックしてサイドパネルを開きます。

### ソースからビルドする場合（開発用）

1. リポジトリをクローンし、ビルドして `dist/` を生成します。
   ```bash
   npm install
   npm run build
   ```
2. `chrome://extensions` で「デベロッパーモード」を有効にし、「パッケージ化されていない拡張機能を読み込む」から生成された `dist/` を選択します。

## 使い方

### 01 対象タブ・02 保存先

- **対象タブ**: 撮影・監視・即録画の対象タブを選択します。
- **保存先**: ダウンロードフォルダ内のサブフォルダ名（デフォルト `capture-relay`）を指定できます。「毎回保存先を選ぶ」を ON にすると保存時に OS のダイアログが開きます。

### 03 静止画

- **画面全体**: 対象タブの表示領域を PNG として保存します。
- **範囲指定**: 対象ページでドラッグして切り抜きます（Escape で取り消し）。
- **要素指定**: 対象ページで要素をクリックして切り抜き、CSS セレクタをトリガー欄に反映します。

### 04 録画

1. **対象** を選択します（`現在のタブ` / `タブを選択` / `画面・ウィンドウ`）。
2. タブ全体以外を撮りたい場合は、**範囲指定** または **要素指定** で対象領域を確定します（`全体に戻す` で解除）。
   - 確定した範囲はページ上に赤い破線のガイド枠として常時表示されます（枠内のページ操作はそのまま可能）。
   - ガイド枠は左上の **「⋮⋮ 移動」** ハンドルで移動、右辺・下辺・右下角のハンドルで幅・高さを調整できます。
   - **要素指定** の場合はウィンドウ幅変更・スクロール・要素リサイズに自動追従します（手動で移動・リサイズするとその位置に固定）。
3. **● 録画** → **■ 停止** で WebM を保存します。
4. DOM トリガーで自動録画したい場合は、先に **事前準備** を押してからトリガーを有効にします。**録画中はサイドパネルを閉じないでください。**

### 05 録音

- **● 録音** → **■ 停止** でマイク音声を **WAV** ファイルとして保存します。
- Side Panel の仕様上初回のみ権限プロンプトを出せないため、未許可時は自動で権限許可タブが開きます。上のダイアログで「許可」を押すとタブは自動で閉じます。

### 06 DOMトリガー

例：`.modal[data-state="open"]` が DOM に現れたら、その領域を撮影する。

- CSS セレクタ：`.modal[data-state="open"]`
- 条件：`出現`
- 操作：`PNG保存`
- `対象要素を切り抜く`：ON
- 「監視開始」で有効化。

要素の出現/消失は `MutationObserver` 、クリックはキャプチャフェーズのイベントリスナーで検知します。開始時に存在する要素は「出現」とは判定しません。一度消えて再出現したタイミングが対象です。クリック/変化の重複発火防止に 800ms のクールダウンがあります。`captureVisibleTab()` の API 制限を考慮し、自動撮影はさらに 900ms 以上あけます。

## 既知の制約

- **ネイティブ OS 範囲選択は未実装。** 範囲指定・要素指定での切り抜き録画は Chrome タブ録画（`現在のタブ` / `タブを選択`）で利用できます。他アプリのウィンドウや「画面・ウィンドウ」録画での任意範囲切り抜きには対応していません。
- **録画・録音はパネル存続中のみ。** パネルを閉じると録画・未保存メディアが失われます。バックグラウンド常駐は Offscreen Document 方式へ拡張する余地があります。
- **共有画面の音声** の有無は OS / Chrome / 共有対象次第です。複数の音声ソースのミキシングは未実装です。
- **選択済み別タブの静止画** は対象タブをアクティブにしてから `captureVisibleTab()` します。非アクティブタブをそのまま撮影する機能ではありません。
- **現在のタブ（即録画）** はツールバーアイコンのクリックで `activeTab` を付与したタブでのみ動作します。別タブへ移動した場合は対象タブ上でツールバーアイコンをもう一度クリックするか、「タブを選択」を利用してください。
- `chrome://` 等の保護ページへの DOM スクリプト注入はできません。
- **DOM イベント時刻と動画フレームは完全同期しません。** ログにイベントのエポックミリ秒と録画開始からのオフセットを記録し、後編集用に関連付けます。MediaRecorder のエンコード・通知は非同期です。
- トリガーで録画開始/停止する場合は、事前準備済みストリームと開いたサイドパネルが必要です。パネルが閉じていれば記録操作は実行されません。
- ページ内の CSS 変化のみで DOM の属性/構造が変わらない場合、`MutationObserver` の出現判定では捕捉できません。CSS 可視性の変化やページ側のカスタムイベント、ネットワーク通信による変化は未対応です。
- 同時に設定できるトリガーは 1 ルール / 1 タブ。監視対象タブのページ移動では再注入を試みますが、制限 URL には再注入できません。

## 設計

```text
src/panel.ts      UI / MediaStream / 録画クロップ / WAVエンコード / MediaRecorder / DOMトリガー操作
src/content.ts    DOM picker / 録画ガイド枠（移動・リサイズ・追従）/ MutationObserver / click監視
src/background.ts Service Worker / action起動 / PNGキャプチャ・クロップ・保存 / ログ永続化
src/rect.ts       矩形変換・保存フォルダサニタイズ・ファイル名生成
src/types.d.ts    必要なChrome拡張API・メッセージ定義（最小限）
public/           manifest.json / UI HTML / CSS
scripts/          ビルド後の静的ファイルコピー・ZIPパッケージ化
```

`chrome.runtime.sendMessage` で `CAPTURE` / `ARM_TRIGGER` / `TRIGGER_FIRED` / `SET_RECORD_GUIDE` / `RECORD_GUIDE_MOVED` 等を受け渡し、撮影は Service Worker、動画・音声の記録はサイドパネルが担当します。ロギングと設定は `chrome.storage.local` を使用。UI はプロトタイプの依存最小化を優先して **vanilla TypeScript** で実装しています（React 未使用）。

### 権限

`sidePanel`, `tabs`, `activeTab`, `scripting`, `downloads`, `storage`, `tabCapture`, `desktopCapture`、および `<all_urls>` のホスト権限を使用します。`<all_urls>` を指定している理由は、Side Panel から選択した任意タブの `captureVisibleTab()` 撮影およびオンデマンドの DOM 監視注入を行うためです。撮影・監視対象はユーザーが UI で指定したタブに限定し、データはローカル保存のみ行います。

## 開発

```bash
npm install
npm run typecheck
npm run build
npm test
npm run package
```

- `npm run package` で `dist/` をクリーンビルドし、`release/capture-relay-v<version>.zip` を生成します。
- GitHub Actions（`.github/workflows/ci.yml`, `.github/workflows/release.yml`）で `main` への push・PR 時に型チェック／ビルド／テスト／ZIP パッケージ化と Artifact アップロードを自動実行します。`Release` ワークフローを手動実行（または `v*` タグを push）すると GitHub Release を自動作成します。
- `@types/chrome` に依存せず、Chrome API のこの試作で利用する部分だけを手動宣言しています。将来の拡張では公式定義型を依存に追加して型の網羅性を高めてください。
